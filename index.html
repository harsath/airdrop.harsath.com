    How it works

    The short version: your browser encrypts the file, uploads the encrypted bytes to storage, and the other devices download and decrypt them. The storage only ever sees scrambled bytes. Files are deleted after 3 hours, or right after the first download if you tick burn after read.

    Rooms and keys

    • Link room: the part of the link after # is a random key. Browsers never send that part to any server. The room's name on the server is a one-way hash of the key.
    • Password room: your browser stretches the password (PBKDF2, 600,000 rounds) into an encryption key, which never leaves the browser, and a separate proof that lets the server check you know the password. Five wrong tries locks you out for 15 minutes.

    What the server can see

    File sizes, upload times, and which anonymous browser uploaded them. Not file names, not contents, not the key or password.

    For the nerds

    • Backend: Supabase. Anonymous auth gives each browser an ID, Postgres row-level security limits every table, file and realtime channel to room members, Storage holds the encrypted files, and Realtime pushes new files and who's online.
    • Encryption: AES-256-GCM via WebCrypto, a fresh random IV per file and per name.
    • Uploads: resumable (tus) in 6 MB chunks, so flaky connections retry instead of failing.
    • Async: the other device doesn't need to be online when you send.
    • Limits: 50 MB per file; files are held in memory while encrypting and decrypting.
